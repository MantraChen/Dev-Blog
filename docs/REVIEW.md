## 写作工作台追加检查（2026-10-25）

本轮基于 `6fc79fb3cc8abec2f87b134ff140d5b9b59775d5`，位于 `feat/writing-workflow`。新增自动保存/浏览器恢复、私密预览、图片上传和文章版本历史；以下记录仅针对本轮增量，后文保留前次全仓审查结果。验证使用本地隔离数据库，朋友仓库 PR #13 保持关闭，未变更生产数据或部署。

- **内容完整性**：私密工作草稿与公开文章分表；保存、发布、恢复使用事务。草稿版本和文章基线版本分别检查，过期标签页返回 409；重复 slug 发布失败会回滚并保留草稿。历史恢复只写入草稿，需再次发布，每篇最多保留 30 个文章版本。
- **权限与输入**：草稿、历史和媒体管理接口要求管理员会话及同源写入；完整预览禁止索引和缓存。图片校验实际格式并完整解码重编码，拒绝 SVG、动画、伪装格式、超过 8 MiB / 16,777,216 像素的输入；使用随机 UUID 文件名，去除元数据，限制处理并发和上传频率。
- **媒体访问**：文件不置于静态公开目录，必须由应用判断是否被已发布文章引用。公开图片支持 ETag，撤下公开引用后即使携带旧 ETag 也返回 404。浏览器/第三方已经下载的副本无法收回；不公开列出的文章仍允许直接链接访问。
- **恢复与退出**：断线保留当前标签页的恢复副本，可下载 JSON；刷新后重新打开草稿时提供恢复选择。退出登录清理恢复存储，并通知其他编辑标签页停止保存，避免未完成的请求重新写回缓存。浏览器存储失败会显式提示；该机制不能替代服务端备份，关闭标签页后新开会话不保证找到原副本。
- **性能边界**：自动保存延迟 800 ms、预览延迟 300 ms；单进程最多同时处理两张图片，输出最长边 2048 像素；近期媒体查询有索引。每次保存仍传输完整正文，后台文章列表仍全量读取，不承诺大型内容库或高并发性能。未引用图片保留以支持版本恢复，需监控磁盘，暂未实现自动垃圾清理。
- **部署边界**：新增迁移 007；媒体默认保存在 SQLite 旁的 `media` 目录，可配置 `MEDIA_DIR`。现有部署器的备份仅包含数据库，重新上线前必须扩展为数据库与图片文件成套备份/恢复；不能用 Caddy 静态目录绕过图片鉴权。回退到不支持媒体路由的旧版本会导致新增图片暂时无法展示，应保留文件并采用兼容的回退版本。

本地验证：`npm run check` 为 0 errors / 0 warnings / 0 hints，**44 项测试通过**；独立域名和 `/howielog` 两种配置的生产构建及真实 HTTP 验收通过，包含草稿隔离、并发冲突、恢复、图片权限与缓存失效、CSRF、分块请求大小限制。`npm audit` 为 **0 条已知漏洞**。浏览器实际检查中文编辑、断线后刷新恢复、多标签页冲突、明确发布、封面文件上传、剪贴板图片上传、双栏预览、历史列表/内容对照和跨标签页退出；最终编辑页无控制台错误。浏览器工具在历史恢复确认框上出现控制超时，恢复事务及不自动发布行为由单元和 HTTP 测试覆盖，未将该确认步骤计作浏览器验收通过。

未发现本轮新增代码中的待修复高危问题，但这不是生产渗透测试。Linux/systemd、反向代理和生产恢复演练仍须在实际环境执行；之前 GitHub Actions 受账号账单限制，不能以本地 Windows 结果代替云端/Linux 验证。

## 性能观察

首轮 500 篇合成文章的全量正文读取约 10.6MB，新单页约 0.43MB，元数据查询约 69KB；渲染缓存降低重复解析。此轮另对 1,000 篇、每篇约 20,250 字符的合成内容比较稀有关键词计数查询（9 次中位数）：原 LIKE 扫描 **12.630ms**，FTS 候选 + LIKE 确认 **0.147ms**，两者均返回 1。这个对比不包括 worker 启动、分页行加载和网络时间，不代表生产 QPS/P95。

FTS 索引增加磁盘与写入维护成本。短查询、常见关键词和总数统计仍可能昂贵，worker 隔离和队列限制提供资源边界，不保证任意数据规模下都快速。首次生产迁移须测量索引建立时间与磁盘余量。

## 上线与回退

1. 先停旧 webhook，做生产库一致备份；旧部署工具可能仍执行覆盖式旧脚本。不要只合并 main 就视为完成上线。
2. 更新到 Node 24.22.1+（同主版本），配置绝对 DATABASE_PATH、ADMIN_PASSWORD_HASH、HOST=127.0.0.1，检查 Caddy 转发和 ACL。详见 [Windows 部署说明](../deploy/setup.md)。
3. 用生产副本验证 005/006 迁移、汇总总数和 FTS 索引，再安排短暂维护窗口。后台保留策略启动后会删除过期原始明细，汇总保留；需保留迁移前备份。
4. 切换后核验 release 健康检查、原文章 URL、搜索、管理、统计和备份。故障优先回退到能读取汇总表的版本；不自动覆盖数据库，避免丢失新写入。
5. Linux 替换方案见 [环境评估](ENVIRONMENT.md)。建议先优化当前环境，再在独立候选主机验证；没有执行服务器购买、DNS 切换或生产迁移。

仍需用户侧完成的外部事项只有真实服务器上线/恢复演练、持续容量监控与 GitHub 账单解锁。匿名统计不是身份系统、SQLite 不是跨主机数据库、第三方评论有网络依赖，这些是明确保留的架构/产品边界。
