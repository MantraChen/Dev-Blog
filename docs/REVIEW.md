## 上线顺序与限制

1. 先停旧 webhook 自动部署，保存生产数据库的一致备份。旧 webhook 可能仍调用旧的覆盖式部署脚本，不能仅靠合并代码完成迁移。
2. 按 [部署文档](../deploy/setup.md) 更新 Node 与 NSSM 环境变量，确认数据库指向现有绝对路径、回环绑定和反向代理配置。
3. 合并后更新服务器上的部署工具 checkout，手动执行新版脚本并核对健康检查、文章与管理登录，再重启 webhook。
4. 本轮迁移保留兼容字段，失败时恢复旧服务配置，不自动覆盖数据库。后续如引入破坏性迁移，需另行设计恢复步骤；不要直接恢复备份覆盖迁移后的新写入。
5. 对旧的非法日期仅保留并在 feed 中容错，不猜测其业务时间；若生产库存在此类记录，应由作者修正。未在本地操作或验证真实生产数据。
