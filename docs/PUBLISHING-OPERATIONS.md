## 发布和合并

预检检查必填内容、slug 与旧地址占用、重复标题、翻译分组冲突、摘要、封面、图片说明、内部文章链接和隐藏状态。错误阻止编辑器发布；提示由作者复核后继续。没有上传封面时仍可使用自动分享图。直接 API 和定时发布仍执行发布 schema 及版本校验，提示类检查不改变既有自动发布计划。

外链检查只处理 Markdown 链接和图片中的 HTTP(S) 地址，每次最多 20 个，最多两个并发请求，总时限约 30 秒，每个地址最多三次重定向。结果区分 `ok`、`broken`（404/410）、`blocked` 和 `unverified`；403、429、网络超时不被误判为死链。只访问常规 HTTP/HTTPS 端口，拒绝 URL 账号密码、内网和特殊 IP，DNS 结果验证后固定连接地址，每次重定向重新校验。不发送登录 Cookie，不读取响应正文，成功及明确结果短暂缓存。该检查会向目标网站发出请求；不会发送文章正文。

合并使用编辑器已知基线、当前本地数据和最新服务端数据。不同字段或不同位置的正文改动可合并；重叠改动需手动解决。应用合并仍检查草稿版本和文章版本，期间发生其他写入会拒绝保存。历史对比和合并都设置计算上限；超大变更回到人工对照。共同的已发布版本若已从最近 30 个历史版本淘汰，需下载当前副本再从最新版本重新编辑，不猜测基线。

现有文章迁移后默认语言为 `zh-CN`，请在编辑时调整原有外语文章；分组键例如 `sqlite-backup-guide`。每个未删除的翻译分组内，同一种语言只能有一篇文章。未发布、隐藏或回收站文章不进入语言切换、RSS、搜索和站点地图。文章导入导出保留语言、分类和分组键。

## 草稿分享与通行密钥

分享链接使用 256 位随机令牌，数据库只存 SHA-256；创建后仅展示一次完整 URL。每篇草稿最多 10 个有效链接，全站最多 200 个，最长 7 天。分享包含快照正文、元数据及它引用的本地图片；图片请求同样检查令牌和引用范围。快照和素材仍在使用的图片不能从媒体库删除。

分享页及图片始终 `private, no-store`，使用 `noindex, nofollow` 和 `Referrer-Policy: no-referrer`，不记录文章浏览量、不加载评论。发布、丢弃草稿、进入回收站、到期或手动撤销后停止访问。恢复完整备份会撤销全部分享链接，防止旧授权复活。已经复制或下载的内容无法追回。反向代理访问日志应屏蔽 `/share/`、`/share-media/` 的完整路径，避免把链接令牌写进长期日志。

`WEBAUTHN_ORIGIN` 指定精确来源，默认取服务进程的 `SITE_URL`。生产必须使用 HTTPS；localhost/127.0.0.1 仅用于开发。通行密钥绑定域名，换域名后需重新注册。共享域名的路径不是安全隔离边界，朋友站点的同源代码也必须可信。

注册、删除密钥需要再次输入管理员密码，最多 10 把。挑战有效期 5 分钟且只能用一次；注册挑战还绑定当前会话。验证来源、RP ID、签名、用户验证标志和计数器。登录结果使用既有 Secure / HttpOnly / SameSite=Strict Cookie；失败尝试共享登录限流。会话列表只展示管理用摘要 ID，不向浏览器返回其他设备的登录令牌。

密码登录继续作为恢复方式，请妥善保存强密码。内容备份恢复会退出所有会话并清除待用挑战，**保留当前通行密钥及最新计数器**，不会复活备份中的已撤销密钥；在全新机器恢复时，先用配置的管理员密码登录，再注册密钥。真实手机、生物识别和安全密钥需要管理员本人在目标 HTTPS 域名完成注册验收。

## 异机备份配置

采用 [restic](https://restic.readthedocs.io/en/stable/030_preparing_a_new_repo.html) 加密备份，支持其 SFTP、S3 兼容存储及其他后端。应用先生成并校验已有的完整恢复集，再上传；后台不填写存储密码、不自动创建或购买存储资源。

1. 在服务器安装 restic，创建独立备份仓库；建议专用于该博客。以服务账户运行 `restic init` 完成初始化。
2. 在私密服务环境配置 `RESTIC_BINARY`、`RESTIC_REPOSITORY` 或 `RESTIC_REPOSITORY_FILE`、`RESTIC_PASSWORD_FILE`。密码文件只能由服务账户及管理员读取；不要使用应用管理员密码作为备份密码。配置示例见仓库 `.env.example`。
3. Linux 推荐把 restic 缓存放在 `/var/lib/dev-blog/restic-cache`，设置 `RESTIC_CACHE_DIR`。SFTP 私钥和 known_hosts 放在服务能读取的专用位置，通过 SSH 配置指定，不要关闭主机密钥校验。现有服务有 `ProtectHome=true`，不能假定它能读管理员的 `~/.ssh`。
4. Site health → Back up & upload，等待完成后执行 Verify remote data。该按钮会读取并校验仓库数据，耗时和带宽取决于仓库规模。页面只显示经过处理的状态；失败时用服务账户单独运行 restic 诊断，避免将含存储地址或凭据的输出贴到公开 issue。
5. 成功后再开启每日上传。每 24 小时最多自动尝试一次；失败留在健康面板，可以手动重试。长操作后台运行，一次只允许一个，单命令最长 30 分钟。服务重启中断后需检查状态并重试。

本地自动保留数可设 3–365；只清理已生成且可识别的 `daily` / `remote` 恢复集，手动备份、安全备份、无法读取的清单、缺失数据库或未知格式目录均保留。清理资格检查不代替完整性校验和恢复演练。先 Preview cleanup，再决定 Apply cleanup。自动清理仅在开启策略且生成新备份成功后运行；上传流程仅在远端成功后淘汰本地自动备份。单独启用的本地每日备份也可应用本地保留策略。

远端保留最近 3 份，以及 7 日、4 周、12 月恢复点，使用站点来源及前缀派生的专属标签，并按标签分组，避免 UUID 源目录令保留策略失效。不会按此策略删除其他站点的标签。不同应用实例不要共用相同站点标识。变更域名/前缀后标签会改变，旧标签需人工归档。有关保留语义见 [restic retention](https://restic.readthedocs.io/en/stable/060_forget.html)。

恢复时，先用 `restic snapshots` 选择恢复点，再用 `restic ls <snapshot>` 找到包含 `manifest.json` 的目录。使用 `restic restore <snapshot>:<该目录> --target <隔离目录>/<manifest中的UUID> --verify` 仅恢复备份子树，避免复制 Windows 系统父目录的权限。将恢复集放入当前版本的 `FULL_BACKUP_DIR`，按原有 Check and preview restoration 流程恢复。密码文件丢失后无法解密；密码及服务配置需另外安全保管。

完整备份仍要求单应用进程；不同进程间没有统一的维护锁。远端任务运行期间禁止在线恢复。恢复后自动远端任务配置会清除，检查目标后重新启用。不要让反向代理直接公开数据库、媒体目录或备份目录。

## 分享图和性能

分享图只读取本站上传的封面，不在服务器下载外部封面 URL。标题及标签经过文本转义，最多两张同时生成，内存缓存最多 16 张且合计不超过约 16 MiB。请求始终先检查文章当前公开状态，撤稿后不从缓存返回图片。外部封面文章生成标题与标签卡片。Linux 建议安装 `fonts-noto-cjk`，可用 `SHARE_CARD_FONT_FILE` 指定字体文件；具体字形会受系统字体影响。

Mermaid 进入视口附近才加载；超过 4,000 字符的图表需点击 Render diagram。继续保留 strict 模式、源码回退、10,000 字符及 200 条边限制。大型绘图库的产物仍有较大的分块，但普通页面不加载，无需为消除构建提示而删除已有图表功能。

相关文章改为索引化的标签关联表及候选集合查询，避免对每篇候选文章重复解析全部标签。`npm run test:scale` 使用 5,000 篇独立测试文章，测量英文 FTS、中文短词、相关文章、年度汇总和过滤 RSS，并检查私密内容过滤。数据是测试夹具，结果不能换算为生产吞吐或容量承诺。

## 验证与环境边界

`npm run verify:all` 在本机运行类型检查、单元测试、规模回归、根路径和 `/howielog` 的构建与 HTTP 验收、依赖审计。`RESTIC_TEST_BINARY` 指向安装好的 restic 后，`npm run test:restic` 会建立临时加密仓库，执行上传、读取校验、保留预览、解密还原和应用恢复，不连接真实存储。

CI 增加手动触发入口、Node 24.22.1 和规模回归。Linux 根路径任务安装 Caddy/restic/中文字体，并运行 `tests/linux-rehearsal.mjs`：在隔离目录和临时 systemd 单元验证权限限制、Caddy 反向代理、异常退出自动重启、数据持久化和完整恢复。脚本拒绝在非 GitHub-hosted runner 上运行，避免误操作生产服务。

当前用户没有可用 Linux 测试服务器及异机存储；本轮完成 Windows 本地验证和临时 restic 仓库演练。GitHub Actions 仍因账号账单锁定未启动，需要账号所有者解锁后重跑。Linux 脚本已做静态检查，**没有将其计为已运行通过**；真实 HTTPS、存储网络权限和设备通行密钥也须在目标环境验收。
